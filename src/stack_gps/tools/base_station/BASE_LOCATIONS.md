# 베이스 위치별 좌표 레지스트리

> 원안: 박찬미 (PR #42). 장소 이름·코스 대응·복원 조건을 덧붙였다.

베이스 수신기(EVK-F9P)는 한 번에 **한 위치의 좌표만** `TMODE FIXED` 로 저장한다
(`setup_base.py` 가 RAM+BBR+FLASH 에 쓴다). 안테나를 다른 위치로 옮길 때는 그 위치의
좌표로 다시 설정하고, **그 위치에서 기록한 웨이포인트만** 사용한다.

좌표의 높이는 해발고도가 아니라 **WGS84 타원체고**다.

## 위치 ↔ 코스 대응

웨이포인트 절대좌표 = **베이스 좌표 + RTK 기선**이라, 코스 CSV 는 기록 당시의 베이스
좌표에서만 의미를 가진다. 측량일과 코스 시작점 좌표로 맞춘 대응은 아래와 같다.

| 위치 ID | 그 위치에서 기록한 코스 |
|---|---|
| `outdoor_20260818` (원주 운전면허시험장) | `waypoints_wonju_license_20260818_160511.csv` (지정 구간 3종 포함) |
| `halla_20260819` (한라대, MBD 시험) | `waypoints_halla_univ_20260819_182657.csv` (303점, 전 구간 FIXED) |
| `outdoor_20260801` (한라대) | **없음** — 2026-08-19 정리 시 삭제 |
| `outdoor_old_20260724` (한라대) | **없음** (위와 같음) |
| `rooftop_20260723` | 없음 |

> 코스 파일 이름에 **장소**를 넣는다(`waypoints_wonju_license_...`). 이름이 애매하면
> 파일 첫 줄 lat/lon 으로 구분할 수 있다 — 한라대 `37.3041 / 127.9075`,
> 원주 운전면허시험장 `37.3006 / 127.9791`.
>
> 삭제된 한라대 코스가 필요하면 git 이력에 남아 있다:
> `git log --diff-filter=D --name-only -- src/stack_gps/waypoints/`

## 이 표만으로 복원되는가 — 소프트웨어는 되고, 물리에 조건이 붙는다

**수신기 쪽은 이 세 숫자면 완전 복원된다.** `setup_base.py --lat --lon --height` 가
나머지 설정(1Hz 항법·UART2 RTCM 6종)까지 같이 다시 쓴다.

다만 베이스는 **자기가 어디 있는지 모르고 우리가 말해 준 값을 믿는다.** 안테나를
그때와 다른 자리에 세우면 로버 위치가 **전체적으로** 그 차이만큼 밀린다 — RTK FIXED 는
멀쩡히 뜨므로 상태줄로는 안 보인다. **삼각대 높이도 포함**이다(타원체고가 그만큼
틀어진다). 그래서 표의 "안테나 설치" 칸을 반드시 채운다.

그리고 코스 재사용에 필요한 건 절대 정확도가 아니라 **일관성**이다. 그때 측량이 진짜
위치에서 20cm 틀렸더라도 같은 좌표를 선언하고 같은 자리에 세우면 그때와 같은 프레임이
재현돼 CSV 가 맞는다. 반대로 같은 자리에서 **재측량하면** 값이 cm 단위로 달라져 코스가
그만큼 밀린다 — **옛 코스를 쓸 거면 재측량이 아니라 표의 숫자를 그대로 넣는 것이
정답이다.**
