# stack_avoid — 요구사항

**담당: 이기돈** · 산출물: 회피 단독 주행 (8/2) — 하위 제어 보수 겸임(김재민에게서 인수)

## 역할

장애물 인지, 회피 가능 판정 재료(TTC·측방), 회피 경로

**시나리오:** 주행 중 전방에 장애물 → 회피 경로로 피해서 지나간 뒤 원래 경로로 복귀.

**구현 방식:** GPS 웨이포인트의 누적 station+1m 시작점 → 장애물 옆 회피점 →
회피점을 투영한 GPS station+2.7m 복귀점을 3차 곡선으로 연결한다. 매 유효 스캔마다
재생성하고 지나간 구간을 제거한다. +1m 시작이 불가능할 때만 현재 차량 위치에서
재계획한다. 실제 제어점은 회피점이며, 통과 후 복귀 웨이포인트로 바뀐다.
상세 계약은 [AVOID_STATION_PATH.md](../../docs/AVOID_STATION_PATH.md)를 따른다.

2026-09-14 표면 모델: 인접 반사점을 연결된 2D 윤곽으로 구성한다. 최근접 거리는
검출·TTC에 쓰고 목표점은 관련 면의 앞뒤 범위·끝점에서 생성한다. 선분을 차량
폭·여유만큼 팽창시킨 영역의 실제 단면으로 측방 점유 구간을 구한다.
깊이 범위로 윤곽을 잘라 가상의 장애물 끝을 만들지 않는다. 고립점도 보존한다.
설정·한계·검증은 [AVOID_SURFACES.md](../../docs/AVOID_SURFACES.md)를 따른다.

## 계약 (이것만 지키면 나머지는 자유)

- 입력: 전방 2D LiDAR (100ms), GPS 웨이포인트 창·누적 station·위치·헤딩, VehicleVector 속도(TTC).
- 출력: `/perception/avoid` (`fma_interfaces/AvoidStatus`).
  - `avoidable`(TTC·측방 여유)은 판정 **재료** — lane/waypoint→avoid 전이 결정은 MGM.
  - `ttc`: 관측 통로의 gap/실속도 진단값. v2 MGM은 TTC/avoidable로 E-stop을 만들지 않는다.
    계산은 정적 장애물 가정(거리 ÷ 자차 속도)으로 충분.
  - `points[]`: vehicle frame 회피 경로 — **점 개수: 1개** (팀 합의 변경 2026-07-29, 현재 추종할 회피 목표점 하나. 기동 진행에 따라 매 주기 갱신). `maneuver_done`: 복귀 트리거.
  - `v_suggest`: 회피 기하로 결정한 속도 — avoid 스테이트의 종방향은 이 값이 지배.
- **`maneuver_done` 주의 — 스캔 기반의 유일한 함정.** 장애물을 지나치는 중에는 장애물이
  전방 스캔 시야에서 사라지지만 아직 차 **옆에** 있다. "스캔에 안 보임 = 완료"로 구현 금지.
  측방 클리어런스 확인이나 최근 장애물 위치의 짧은 유지·감쇠 같은 내부 상태는 허용
  (이건 맵 생성이 아니라 정상적인 내부 구현이다).
- **복귀 경로:** 항상 회피점 station+2.7m 웨이포인트에 3차식으로 연결한다.
  관측된/기억된 장애물과 footprint·곡률을 검사하며, 미관측을 이유로 직선 꼬리를
  추가하지 않는다. 복귀 도달과 GPS 정렬을 확인한 뒤 완료한다.
- **회피 경로 없음:** 스택은 빈 points와 실패 사유를 발행한다. 일반 장애물 대응
  상태의 MGM은 이 입력에서 차선 주행을 계속하지 않고 정지한다. 별도 E-stop도 유지된다.
- 금지: 이 스택에서 정지/모드 결정 금지. "회피 경로 요구" 같은 별도 요구 개념도 없음 — 회피는 스테이트다 (CLAUDE.md §4).

## 공통 규칙 (CLAUDE.md)

- MGM 계약은 `fma_interfaces` 메시지로 유지한다. 별도 RViz 진단 Path/Marker 토픽을 발행한다.
- 경로를 내는 스택은 전부 동일 ref points 포맷 — {x, y, yaw, curvature}, vehicle frame (§5.4).
- 판단 로직(모드 전환·정지 결정·우선권)은 MGM 스테이트 머신에만 존재한다 (§4, §5.1).
- 실행: `ros2 run stack_avoid stack_avoid_node`
