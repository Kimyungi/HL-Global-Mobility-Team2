# 호모그래피 실측 캘리브레이션 가이드 (stack_lane)

> 목적: 카메라 픽셀 → vehicle frame 미터 좌표 변환(H)을 실측으로 확정한다.
> 현재 placeholder H 사용 중 = 실주행 투입 금지 상태 ([node.py](stack_lane/node.py) docstring).
> 작성: 2026-08-11 김윤기·Claude. 도구 설계 배경은 PROJECT_BRIEF.md §9 참조.

## 0. 전제 조건

- **카메라 브래킷이 최종 위치·각도로 확정**되어 있을 것. 이후 브래킷을 다시 조이면
  전 과정 재실측이다. 흔들리게 조여져 있으면 먼저 고정부터.
- 차량을 **평평한 곳**에 주차하고, 실측이 끝날 때까지 차량·카메라를 움직이지 않는다.
- depthai 3.x가 설치된 PC(현 산업용 PC)에서는 캡처를 **`capture_calibration_frame_v3.py`**로
  한다. 원본 `capture_calibration_frame.py`는 v2 API라 실행되지 않음 (2026-08-11 확인).
  클릭 단계(`calibrate_homography.py`)는 depthai 무관이라 그대로 사용.

**준비물**: 줄자 5 m 이상(2개면 편함), 마스킹테이프 또는 분필, 추(끈+너트 등 다림줄),
기록용 종이/폰. 인원 2명 권장(1명 측정, 1명 기록·입력 대조).

## 1. 원점·축 표시 (10분)

1. **원점(0,0)** = 카메라 렌즈 중심에서 추를 늘어뜨려 지면에 수직 투영한 점.
   테이프 십자로 표시.
2. **x축(전방)** = 차량 전방 진행 방향. 원점에서 차량 중심선과 **평행하게** 줄자를
   전방으로 곧게 편다. 방향 기준은 차체 대칭 요소(앞뒤 엠블럼, 루프 중앙선 등)로
   잡을 것 — 카메라가 살짝 틀어져 있어도 H가 흡수하지만(도구 docstring), **차량
   전방 방향 자체를 잘못 잡으면 그대로 조향 바이어스가 된다.**
3. **y축** = x축에 직각, **좌측이 +**. 직각은 3-4-5 삼각형(0.9 m/1.2 m/1.5 m)이나
   두 번째 줄자로 잡는다.

## 2. 마커 배치 (20분)

노드가 실제로 쓰는 범위(x 2.0~6.0 m — `points_x_start` 2.5, `points_x_end` 6.0,
lookahead 3 m)를 덮도록 **fit 8점 + 검증 4점**을 격자로 깐다. 제안 배치:

| 용도 | (x, y) [m] |
|---|---|
| fit | (2, -1), (2, +1), (3.5, -1.5), (3.5, 0), (3.5, +1.5), (5, -1), (5, +1), (6, 0) |
| 검증(v) | (2.5, 0), (3, +1), (4.5, -1), (6, +1.5) |

- 정확히 이 좌표일 필요는 없다 — **실제로 놓인 자리를 cm 단위로 재서 기록**하는
  것이 핵심. 배치값과 기록값이 다르면 기록값이 진실.
- 측정법: x는 원점에서 전방축을 따라, y는 그 x 지점에서 직각으로 잰다.
- 마커는 테이프 십자 — 클릭할 중심점이 명확해야 한다.
- **한 직선 위에 몰리면 H 계산이 실패한다** — 격자로 분산 유지.
- 배치하면서 캡처 스크립트(3단계)를 미리 띄워 두면 라이브 화면으로 12점이 모두
  프레임 안에 보이는지 확인하며 조정할 수 있다.

## 3. 촬영

```bash
cd ~/FMA_ws/src/stack_lane/tools
python3 capture_calibration_frame_v3.py          # MxID 핀닝·1280x720 기본 적용
```

노출 적응 후 화면이 뜨면, 마커 12개가 모두 보이고 사람·그림자가 마커를 가리지
않는 순간에 **SPACE** → `../captures/calib_frame.png` 저장.

## 4. 클릭 캘리브레이션

```bash
python3 calibrate_homography.py --image ../captures/calib_frame.png
```

- 사진 창에서 마커 십자 중심을 클릭 → 터미널에 그 마커의 실측값을 `x y`로 입력
  (미터, 좌측 +). **검증용 4점은 끝에 `v`**: 예 `4.5 -1.0 v`.
- 잘못 찍으면 `u`로 마지막 점 취소. 12점 다 넣으면 `c`로 계산+저장.
- **여기서의 입력 오타 = 그대로 조향 오차.** 기록지와 대조하며 2인 1조로.

## 5. 합격 판정

`c`를 누르면 재투영 오차가 출력된다. 판정 기준:

- **VALIDATION RMS ≤ 0.10 m, max ≤ 0.15 m** 목표. FIT 오차만 작고 VALIDATION이
  크면 입력 오타 의심 — 해당 점 좌표를 다시 재고 재실행.
- `config/homography_bev_preview.png`를 열어 마커 격자·차선이 **곧게** 펴져
  보이는지 확인 (휘어 보이면 지면 경사 또는 점 오류).
- 산출물: `src/stack_lane/config/homography.json` (+ preview png).

## 6. 적용·보존

1. **노드 실행 시 경로 명시 필수** — 기본 경로가 설치본 내부로 해석되는 문제가
   있어 자동 인식되지 않는다 (2026-08-11 점검):

   ```bash
   ros2 run stack_lane stack_lane_node --ros-args \
       -p homography_path:=$HOME/FMA_ws/src/stack_lane/config/homography.json
   ```

2. 기동 로그에 `실측 호모그래피 없음 — placeholder` 경고가 **안 뜨는지** 확인.
3. `homography.json` + `homography_bev_preview.png` + `captures/calib_frame.png`을
   **git 커밋** (재캘리브레이션 판단·추적용. json에 클릭·실측 점이 함께 저장됨).
4. (선택) 마커 1~2개를 남겨두고 노드 debug 이미지/CSV에서 해당 지점 좌표가
   실측과 ~10 cm 내로 일치하는지 확인하면 끝.

## 재실측이 필요한 경우

브래킷 재조임·충격, 카메라 높이/pitch 변경, 타이어 공기압 큰 변화, 검증 주행에서
좌표 오차가 눈에 띄게 커진 경우.
