# 회피 재계획 및 장애물 대응 수정 검증

- 기존 경로 station에서 0.75m 초과 이탈 시 현재 위치에서 새 경로를 검증한다. 이전 경로는 폐기하되 회피 에피소드, 위치 좌표계, 장애물 기억은 유지한다. 실패하면 다음 유효 스캔에서 재시도한다.
- 최초 경로 생성 실패 뒤 장애물 검출이 일시 해제돼도 에피소드를 유지해 경로 생성이 중단되지 않게 했다.
- 일반 회피 진입 및 GPS 복귀 중 재진입에서 장애물 검출과 경로 유효성을 분리했다. 경로 없음/무효이면 AVOID_ACTIVE 및 정지. 신선한 경로와 주행 조건이 복구되면 회피 속도 램프로 재개한다.
- 장애물이 남아 있거나 경로가 없는 상태는 시간 제한으로 GPS 복귀하지 않는다.
- provider의 avoidable=false(TTC 거절 포함)는 경로가 있더라도 정지를 유지한다. 기존 주차 우선순위, 회피 기능 OFF/구역 제한, E-stop/후진 조건은 유지한다.
- 플래너 상태 변화 로그에 실패 사유/목표 유무/위치 소스/재계획 횟수/이탈 거리를 추가했다.

검증:

- `scripts/v2 build`: 13개 패키지 성공.
- stack_avoid Python: 89개 통과. 실제 로그 마지막 목표·GPS 이동량 기반 0.73877→0.77366m 이탈 재현에서 새 경로 생성, 장애물 기억에 막힐 때 목표 미생성, 실패 후 재시도, 위치 좌표계 유지 포함.
- MGM CTest: 22개 테스트 실행파일 전부 통과.
- 격리 ROS(domain 184, localhost only) 회피 smoke: 장애물+빈 경로에서 AVOID 정지, 새 경로 수신 후 주행, GPS 복귀, E-stop 및 후진 이후 복귀 확인.
- `scripts/v2 check`: V2_INSTALL_READY.
- 당시 19,761개 입력을 수정 코어로 오프라인 재생. 두 번째 장애물 검출부터 기존 E-stop까지 179틱 전체가 회피 소스(2), v_ref=0, 경로 무효 정지로 바뀜. 기존 출력은 차선 소스(0), v_ref=1이었다.

재생 입력 `inputs_v27_layout_v28_semantics.bin`은 원본을 복사한 후 버전만 27→28로 바꿨다. 이번 코어 변경은 Snapshot/Params 바이너리 레이아웃을 바꾸지 않았으며, 출력 의미가 바뀌므로 신규 덤프 버전을 28로 올렸다. 원본 덤프는 변경하지 않았다. 기존 코어 실행파일은 ../replay_v27/core_replay에 보관했다.

이는 기록된 인지 입력을 재생한 결과이며 차량 움직임이 달라졌을 때의 센서 입력까지 계산하는 폐루프 시뮬레이션이 아니다. 현장 장애물 원시 스캔이 없어 실제 현장에서 새 경로 생성 성공 여부는 별도 주행 확인이 필요하다. 실차 런처/주행 인가는 실행하지 않았다.
