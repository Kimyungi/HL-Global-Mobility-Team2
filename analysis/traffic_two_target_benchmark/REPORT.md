# 신호등 1개·2개 추적 비용 비교

실행일: 2026-09-17. 장비: Intel Core Ultra 9 288V, 논리 CPU 8개. 운영 로직 변경 없음.

## 측정 범위

촬영 파일이 현재 captures 폴더에 없어 고정 난수 합성 BGR 영상(640×360)을 사용했다. 새 사진 촬영은 하지 않았다. 실제 운영 함수 select_tracking_candidate, smooth_bbox, ShortTermTemplateTracker, classify_signal_color를 호출했다. 두 대상은 서로 떨어진 고정 박스이며 후보 10개를 비교한다. YOLO 후보 연계·템플릿 갱신 프레임과 템플릿 추적 프레임을 번갈아 처리하고, 매 프레임 각 대상의 HSV 색상을 분석한다. 후보 확정 전에도 색상을 처리하므로 추적만 하는 임시 후보보다 비용이 클 수 있다.

박스 크기는 비교용 가정이며 실제 신호등 크기나 정확도 측정값이 아니다. 1개·2개 순서를 번갈아 각 500프레임씩 8회 실행하고 회차 평균의 중앙값을 비교했다. 운영 센서 노드는 계속 실행 중이므로 시스템 부하에 따른 변동이 포함된다. 전체 다중 대상 상태 머신이나 충돌 해소 알고리즘은 구현·측정하지 않았다.

## 추적 및 색상 처리 실측

| 박스 크기 | 1개 ms/프레임 | 2개 ms/프레임 | 추가 ms | CPU 증가 %p(전체 8개 CPU, 10fps 환산) |
|---|---:|---:|---:|---:|
| 16×12 | 0.059 | 0.118 | 0.059 | 0.007 |
| 40×24 | 0.170 | 0.340 | 0.170 | 0.021 |
| 100×60 | 1.011 | 1.950 | 0.939 | 0.117 |

CPU 증가량은 프로세스 CPU 시간 차이 × 10fps ÷ CPU 8개로 환산했다. 시스템 모니터의 실시간 사용률을 직접 비교한 값은 아니다. 한 코어를 100%로 표시하는 top 기준 증가량은 위 값의 8배다.

## YOLO 포함 계산

동일 합성 영상에서 실제 가중치로 YOLO 30회 측정: 중앙값 30.50ms/추론, 장치 cpu. 추론 2프레임당 1회라는 조건으로 추적 시간과 합산한 계산이며 전체 카메라 파이프라인 실측이 아니다.

| 박스 크기 | 1개 평균 ms/프레임 | 2개 평균 ms/프레임 | 증가율 |
|---|---:|---:|---:|
| 16×12 | 15.31 | 15.37 | 0.39% |
| 40×24 | 15.42 | 15.59 | 1.10% |
| 100×60 | 16.26 | 17.20 | 5.77% |

카메라 입출력, GUI, 정지선 추론, 동적인 추적 실패·복구 비용은 전체 시간 계산에서 제외했다. 10fps의 100ms 간격과 비교하면 이 실험의 추가 비용은 0.06~0.94% 수준이지만 실제 FPS 유지 보장은 아니다.

## 내장 그래픽

YOLO 실행 장치는 CPU로 확인했다. 벤치마크의 추적·색상 처리는 NumPy 배열을 받는 OpenCV CPU 경로이며 UMat/cuda 연산이나 대상별 추가 모델 추론을 사용하지 않았다. OpenCV의 OpenCL 전역 활성 플래그는 true였으나 이 플래그만으로 GPU 실행을 의미하지 않는다. GPU 사용률 계측 도구가 없어 증가 %p는 미측정이다. 추가 GPU 추론 호출은 0회이며 추적 변경에 따른 화면 그리기 비용은 이 측정에 포함하지 않았다.

## 판단

두 대상의 기본 추적 연산 자체는 이 장비에서 부담이 작은 편이다. 기존 추적·색상 부분은 거의 두 배지만 모델 추론 횟수는 늘지 않아 전체 추론·추적 합산 증가율은 약 0.39~5.77%였다. 실제 인식률 개선이나 오른쪽 신호등 미검출 해결 여부는 검증하지 않았다. 재현 스크립트 benchmark.py와 원시 수치 results.json을 함께 보관한다.
