## 기록값과 재구성의 구분

- 위치: lateral.csv의 GPS 위경도. 각 실행 첫 GPS를 원점으로 동/북 m 환산.
  저장소 PathEngine과 같은 111320 m/deg 근사를 사용한다. 헤딩도 lateral.csv 기록값이다.
- 상태: 원본 transitions.csv의 상태를 해당 tick부터 다음 전이까지 유지한다.
  tick 시각은 mgm_snapshots.bin에서 해독한 event_time_ns를 쓴다. 현재 코어로 재생하지 않는다.
- 차량 속도: 직전 스냅샷의 유효한 실측 속도만 표시한다. invalid는 공백이다.
- v_ref: 직전 상태 전이 행에 기록된 값이다. 전이 사이 속도 램프는 재현하지 않는다.
- 회피 참조: 스냅샷의 첫 회피 제어점을 GPS 위치/헤딩으로 지도에 투영한다.
  이는 제공된 참조이며, MGM이 실제 선택했는지는 별도 `참조 소스`와 상태로 확인해야 한다.
  오래된 참조는 현재 점을 회색으로 표시하고 누적 분홍 점에는 포함하지 않는다.
- 전체 nav_msgs/Path 원본과 당시 LiDAR scan은 이 네 실행에 저장되어 있지 않다.
  A·B·C 로그가 있는 두 실행은 기록된 앵커를 생성 시점 근처 GPS 자세로 투영해
  점선으로 연결한다. 이 연결선은 실제 Hermite 곡선이 아니다.
  22:40 실행의 CAN x/y 고정 좌표와 22:54 실행의 적분 좌표를 GPS 고정 경로로 간주하지 않는다.
- 신호 정지선: 06:40:26.836의 제어기 잔여거리 0.21m를 가까운 GPS 자세에서 전방으로 투영한다.
  제어기 설정 거리와 속도 적분을 포함하는 추정이며, 측량/카메라 원본으로 복원한 정지선이 아니다.
  횡선 폭 3m는 표시용이다. 추정선은 해당 시각 이후 같은 지도 위치에 유지한다.
- 정지선 검출: 06:39 실행은 직전 카메라 진단 로그의 stopline 값과 그 로그의 경과 시간을 표시한다.
  다른 세 실행은 직전 MGM 스냅샷의 traffic_stopline_detected 값이다.
- 회색 웨이포인트: 현재 저장소 CSV를 위경도로 투영한다. 당시 파일 보존본이 아니므로
  과거 실행과 동일하다고 보증하지 않는다.
- 약 10Hz GPS 샘플마다 표시하며 중심 이벤트 이후 첫 GPS 샘플을 초기 화면으로 선택한다.
  따라서 76ms처럼 짧은 이벤트의 모든 중간 상태가 화면 프레임에 포함되지는 않는다.
  원본 전이 시각은 이벤트 목록에 별도로 남긴다.

## 검증 / 재생성

- v29 세 실행은 magic/version/snapshot size/params size를 확인한 decoder로 해독했다.
- v28 신호 실행은 기존 `analysis/run_20260914_063951_diagnosis/inputs.csv`를 사용했다.
- GPS 시각에는 가장 가까운 직전 스냅샷을 사용하며 시차 100ms 미만을 assert한다.
- JSON 비유한 수치를 금지하고 전이 tick의 범위를 검사했다.
- Chromium에서 네 탭의 렌더링, 슬라이더, 네 상태 색상, 이벤트 이동,
  제어된 시계의 재생 진행을 확인했다. 실제 화면 캡처도 확인했다.
- `python3 analysis/drive_event_viewer_20260915/build_viewer.py`로 HTML/JSON/PNG를 재생성한다.

생성 스크립트, HTML 템플릿, decoder는 같은 폴더에 있다.
