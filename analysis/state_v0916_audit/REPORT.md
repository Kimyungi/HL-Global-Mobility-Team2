# 스테이트 v09.16 경로·미션 실행 가능성 점검

기준: integration/v2_main `2991216`. 정상 실행문서 경로 01 → 03 → 04 → 05 → 07.
CSV 7개 901행도 보조 점검했다. 차량·CAN·센서를 기동하지 않고 실제 CSV, 실제
GPS PathEngine, 실제 C++ zone_step 및 현재 설정을 사용했다. 주행 코드와 지도는 수정하지 않았다.

**판정: “전체 경로 추종 가능 / 미션 충돌 없음”으로 승인할 수 없다.**
실행 연결 시험은 통과했지만 아래 추종 우려 2건과 조건부 미션 누락 1건을 확인했다.

## 주요 결과

| 우선 | 위치 | 확인한 사실 | 의미 |
|---|---|---|---|
| 높음 | T 주차 참조경로 parking_ref_01 / parking_ref_02 | 실제 주차 로더 계산 최소 반경 0.951m / 0.923m. 설정 최소 반경은 1.15m | 축거 0.595m 기준 필요한 등가 조향각 약 32.04° / 32.79°. 저장소 회피 설정 27.3° 및 주차 30°보다 큼. CSV를 그대로 따라가는 기하학적 여유 부족 |
| 높음 | 04 종점 idx 205 → 05 시작 idx 0 | 좌표 차이 0m. 실행 PathEngine의 접선 방향은 약 69.24° 차이 | 위치 연결만 맞는다. 연결부를 통과할 조향 연속성·회전 공간은 확보됐다고 볼 수 없음 |
| 조건부 높음 | 03 T 주차 진입 idx 145~149 | 2m/s·독립 GPS 5Hz 가상 입력에서 3~4회만 관측되어 진입 0회. 10Hz는 6~7회 관측, 진입 1회 | 실제 새 GPS fix 주기가 낮거나 누락되면 미션을 놓칠 수 있음. ROS 발행 주기가 아니라 새 fix 횟수 기준 |

T 주차의 `enforce_min_radius=False`는 경고만 남기고 경로 선택을 허용한다.
따라서 “경로 선택 성공”은 “차량이 그 곡률을 추종 가능”을 보장하지 않는다.
MPC가 경로를 완화할 가능성은 있으나 실제 제어기 모델·추종 오차·차체 공간을 함께
검증하기 전에는 가능하다고 판정할 수 없다. 반경 경고는 두 참조경로의 전체 길이 기준이며,
실제 후방 벽에서 조기에 멈추는 위치에 따라 해당 곡률 구간을 모두 지나지 않을 수도 있다.

03 주차 진입 시험은 이상적인 GPS 위치·헤딩과 2m/s를 가정하고 실제 PathEngine에서
얻은 위치 index를 실제 C++ zone_step에 입력했다. 샘플 위상 4가지를 각각 확인했다.
5Hz가 이 PC의 실제 측정값이라는 뜻은 아니다. 이번에는 실제 수신 주기를 측정하지 않았다.
미션을 한 번도 진입하지 못하면 완료/실패 기록도 생기지 않아 종점에서 필요한 미션을
기다리는 WAIT_MISSION에 남을 가능성이 있다.

## 정상 확인 또는 충돌로 단정하지 않은 항목

- 실제 운용 경로의 모든 CSV 연결부 위치 차이는 0m.
- CSV yaw 열을 직접 미분하면 다수 급곡률이 보이지만, 일반 GPS는 좌표에서 접선과
  곡률을 다시 계산한다. 따라서 그 수치를 그대로 실행 곡률로 보고하지 않았다.
- 실행 GPS 경로 내부의 최소 반경: 01=365.30m, 03=12.74m, 04=2.98m,
  05=2.06m, 07=12.36m. 모두 설정 기준 1.15m 이상이다. 연결부와 하위 제어기 추종성은 별도다.
- 실행 방향 차이: 01→03 약 2.23°, 03→04 약 10.98°, 04→05 약 69.24°,
  05→07 약 -11.01°. 주차 완료 자세에서 다음 GPS 목표까지의 폐루프 주행은 미검증.
- T 주차 진입 구간은 03 idx 145~149이며, 같은 경로 Traffic/GPS zone [3]
  idx 28~116과 겹치지 않는다. GPS preview에 의한 앞선 zone 활성화는 별도로 존재한다.
- 04 회피 표시 구간 idx 77~205와 평행 주차 idx 185~189는 겹친다.
  상위 코드는 MISSION_ACTIVE 시 회피를 INACTIVE로 만들고 주차 준비/실행에 우선권을 준다.
  동시 제어권 출력은 막혀 있으나, 실제 장애물이 주차 진입부에 있을 때 공간이 충분한지는 미검증.
- T 주차는 03 종점만으로 완료되지 않고 후진·정차·10초·전진 복귀 정차 후 완료.
- 독립 E-stop 대신 상위 ESTOP을 사용하며 회복주행 실행기는 연결되어 있다.
  후방 실제 관측이 충족되지 않으면 정지 대기하는 계약은 유지된다.

## 시험과 재현

- 지도·경로 순서·회피 시험: 60개 통과.
- T 주차 참조·순서 시험: 45개 통과.
- C++ 상태/전이/출력 시험: 29개 통과.
- 추가 주차 zone 샘플링 재현: 5Hz/10Hz × 샘플 위상 4개, 총 8조건.
- 기존 시험 통과는 이번에 확인한 곡률/연결부 문제의 부재를 보장하지 않는다.

산출물: `audit.py`, `metrics.json`, `course.png`, `zone_sampling.py`,
`zone_probe.cpp`, `zone_sampling.json`. 재현 명령:

```bash
python3 analysis/state_v0916_audit/audit.py
g++ -std=c++17 -I src/adas_mgm analysis/state_v0916_audit/zone_probe.cpp src/adas_mgm/core/zone_step.cpp -o /tmp/v0916_zone_probe
python3 analysis/state_v0916_audit/zone_sampling.py
```
