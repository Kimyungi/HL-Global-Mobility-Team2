# GPS station 기반 회피 경로 변경 검증

사용자가 지정한 동작을 반영했다.

1. GPS 웨이포인트 누적 station+1m 시작점에서 회피점으로 3차 곡선을 생성한다.
2. 회피점은 장애물이 없는 측방 후보에서 고르며 실제 제어점으로 발행한다.
3. 회피점의 GPS 투영 station+2m 웨이포인트까지 항상 3차 복귀 곡선을 생성한다.
4. +1m 시작 곡선이 충돌·최소 회전반경 검사에 실패할 때만 현재 차량 위치에서 재계획한다.
5. 매 유효 스캔에 경로를 교체하고 지나간 부분을 제거한다. 예전 경로의 0.75m 이탈 검사를 사용하지 않는다.
6. GPS 자세와 웨이포인트 창을 사용하며 CAN 위치/단일 GPS 목표점으로 대체하지 않는다.

검증 결과:

- `scripts/v2 build`: 13개 패키지 성공.
- `scripts/v2 check`: 새 GpsPath 계약과 설치 경로 확인 성공.
- GPS Python 174개, 회피 Python 110개 통과.
- MGM CTest 22개 실행파일 통과.
- 실제 01/03/04 웨이포인트 CSV에서 보간 및 헤딩 좌표 변환 확인.
- 실제 CSV -> GpsPath -> 회피 노드에서 GPS station+1m 좌표 일치 확인.
- 격리 ROS domain 187, localhost에서 실제 회피 노드와 MGM을 실행해
  회피점 전달, GPS 창 소실 시 빈 Path/정지, 복구 후 새 경로/재개 확인.
- `path_updates.png/svg/json`, `plot_path.py`: 합성 장애물 예시. 첫 계획,
  이동 후 갱신, 회피점 통과 후 복귀 목표를 보여준다. 실차 로그 궤적이 아니다.

관측된 장애물과 기억된 2D 윤곽에 대해 footprint와 곡률을 검사한다. 뒤쪽
미관측을 이유로 직선 꼬리로 바꾸지 않으므로 복귀 곡선에 미관측 영역이 포함될
수 있다. 실제 차량 추종 및 숨겨진 장애물까지 검증한 결과는 아니다.

운영용 통합 런처/주행 인가는 실행하지 않았다. 기존 런처를 재시작하면 새 코드와
확장된 GpsPath 메시지를 같은 install_v2에서 사용한다. GPS 별도 서비스는 유지할 수 있다.
