# PR #108 상위 ESTOP 회복 통합 — 2026-09-16

사용자의 “적용 및 병합 진행” 요청으로 내부 회복 실행기 보류를 해제했다.
원본 PR #108은 main/독립 EstopRequest 기반이다. 현재 integration/v2_main의
09.16 상위 전이 계약에 맞게 기능을 옮겼으며 과거 transition() 전체를 병합하지 않았다.

실행기는 `/planning/estop_recovery`만 발행한다. CAN 목표 출력과 ESTOP 전이의
권한은 MGM에 남는다. 독립 `EstopRequest`, 옛 시간 기반 후진은 연결하지 않는다.
2026-09-17 회복 실행기 지시: 실행기 자체의 실제 전진 이력이 없어도 상위 ESTOP에 진입하면
회복 실행기를 즉시 활성화한다. 실제 후진은 기존처럼 인가·유효 차속·연속 정차
6초·후방 여유 조건을 만족해야 시작한다.
실행기는 신선한 MGM의 비ESTOP 상태를 관측한 뒤 ESTOP 진입을 확인한다.
ESTOP 중 실행기만 재시작한 경우에는 이전 후진 거리 소실로 같은 회복을 반복하지
않도록 자동 후진하지 않는다. MGM 미수신을 비ESTOP 관측으로 취급하지 않는다.

후방은 실측 보정값의 a2 원시 LiDAR를 사용한다. 차체 뒤에서 1.25m(후진 1m +
여유 0.25m), 차체 반폭 0.31m + 여유 0.10m 통로에 장애물이 없어야 한다.
먼 경계의 5개 방향에서 유효한 유한 거리 관측을 요구한다. 미수신/NaN/inf/잘못된
프레임은 빈 공간의 근거가 아니다. 후방 유효기간 0.35초, 차속·MGM·CAN 0.25초.
상위 전방·좌우 센서 소실 자체로 ESTOP을 취소하지 않지만, 실행기에 필요한 후방·차속
관측 소실 시에는 후진을 멈춘다. 고장 시 ESTOP 유지이며 새 prepare 세션에서 재평가한다.

CAN TargetRef 상태 5=ESTOP을 메시지·DBC·프로토콜·전이 로그에 추가했다.
새 raw dump는 v34다. 기존 v33은 동일한 메모리 크기여도 의미가 달라 새 재생기로
처리하지 않는다. 이 PC의 이전 v33 재생기는 `build_v2/replay_archive/v33_local`에 보관했다.
현재 소스의 core_replay/parity_replay/make_sample_dump는 같은 버전 계약을 사용한다.

검증: 14개 패키지 빌드, C++ 29개, 회복 단위시험 11개, 런처 31개,
주차 45개. 격리 ROS에서 기존 전이 및 실제 MGM+실행기의 정지/후진/정차 완료를 검증했다.
실차 센서·CAN 송신·dSPACE 제어기는 기동하지 않았으며, 실제 차량의 state 5 처리와
음수 목표속도 추종은 이번 소프트웨어 시험의 검증 범위 밖이다.

v34 샘플 1,100틱 반복 재생은 동일했으며 기존 생성 코드 비교에서도 불일치가 없었다.
v33 로그는 보관한 v33 도구로 재생하고 v34 도구의 명시적 거부를 확인했다.
다른 PC에서 v33 도구가 필요하면 변경 전 커밋 `d363c3a`에서 빌드한다.
회복 단계·누적 거리는 `/planning/estop_recovery_status`로 확인한다.
MgmState의 과거 recovery_* 진단 필드는 구형 회복기의 값이며 이 실행기의 진행률이 아니다.

2026-09-17 추가 지시로 상위 진입에는 위 감지 활성화 조건을 적용했다.
회복 실행기는 별도 전진 이력을 요구하지 않으며 기존 회복 절차를 유지한다.
