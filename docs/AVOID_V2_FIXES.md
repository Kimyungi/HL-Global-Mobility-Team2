# 회피 로직 실패 수정 결과

2026-09-15 · `New_Avoid_v2`

[수정 전 59개 조건 조사](AVOID_V2_FAILURE_SCENARIOS.md)에서 재현된 제동 검사 누락과 코드상 문제를 수정했다. 물리적인 통과 불가, 센서 결손, 실차 연결 미구현까지 모두 해결됐다는 뜻은 아니다.

## 적용한 수정

1. **표본 사이 제동 검사(V09).** 새 경로와 재사용 경로 모두 이웃 상태 사이의 위치·yaw·조향·속도 변화를 포함해 제동 영역을 검사한다. 중간 상태의 정지 궤적을 기준으로 변화량의 상한만큼 검사 영역을 넓힌다. 확인이 안 되면 구간을 최대 6단계 세분하고, 끝까지 확인하지 못하면 후보를 거부한다. 100ms 다음 상태 하나만 덧붙이는 방식에 한정하지 않는다. 차량 모델·격자 관측이 정확하다는 전제의 보수적인 코어 검사이며 실차 정지 보장은 별도다.
2. **직진 제동의 과도한 여유 수정.** 모든 제동에 최대 조향각을 가정하던 표본 사이 이동 여유를 현재 조향과 목표 조향의 범위로 계산한다. 조향 모델은 목표를 향해 단조롭게 변하므로 이 범위를 벗어나지 않는다. 기본 차체 여유 0.15m는 그대로 적용한다. 회전 영역의 반경도 여유를 포함한 차체 모서리로 계산한다.
3. **통로 경계와 후보 선택.** 5cm 간격으로 찾은 첫/마지막 자유 표본을 그대로 벽 위치로 쓰는 오차를 줄이기 위해 자유·차단 경계 사이를 이분 탐색한다. 남은 통로 폭도 선택 비용에 반영한다. 한쪽 경로에서 실행 경로를 만들지 못하면 좌·우 선호를 달리한 통로 후보를 추가 검사한다. 모든 통로를 완전 탐색하는 알고리즘은 아니다.
4. **감속 선행 거리와 저속 후보.** 속도 제한을 앞당기는 거리에 앞범퍼와 전체 제동 거리를 반영한다. 필요한 경우 통로 안내선에 대해 0.2m/s 저속 목표도 비교하며, 측정 속도에서 가감속 한계를 지켜 접근한다. 최대 속도만 바꿨을 때 같은 실제 속도의 lookahead가 달라지지 않도록 실제 m/s 기준으로 선행 거리를 조절한다.
5. **동일 경로 재수신(P08).** 경계·GPS 경로의 좌표와 경로 식별 정보가 같고 header 시각만 바뀐 메시지는 활성 세션과 관측 지도를 초기화하지 않는다. 실제 경계·경로·식별 정보가 바뀌면 기존처럼 새 정합과 관측을 요구한다.
6. **처리 기한 진단(T01).** ROS callback 35ms 초과로 출력을 무효화할 때 `deadline_hit`도 함께 설정한다.

## 검증 방법

새 `avoid_v2_execution_safety_test`는 S자 중앙 2대/3대와 직선 중앙 2대를 상한 0.2/1.0m/s로 실행한다. 매 valid 프레임에서 새 관측 전 동일 지도에 대해 0~150ms를 5ms 간격으로 샘플링해 차체와 제동 가능성을 확인한다. 별도의 88개 조건 시험도 매 valid 경로의 100ms 뒤 상태가 같은 지도에서 제동 검사를 통과하는지 기록한다.

기존 26개 배치×3회 시험과 88개 속도·간격 조건은 위치·차량 크기·도로 폭을 유지한다. 좁은 구간이나 미관측을 통과하도록 여유를 없애거나 실패 assertion을 삭제하지 않았다. HOLD 프레임 이후 실제 차량의 제동 실행은 재생에 포함하지 않는다.

## 남은 범위

- 직선 중앙 차량 2대·3대 배치는 필요한 길이의 차체·조향·제동 검증 경로를 아직 만들지 못한다. 반대쪽 후보와 저속 후보를 포함해도 HOLD가 남는다. 이것만으로 물리적으로 통과 불가능하다고 판정한 것은 아니다.
- 촘촘한 좌우 교대 배치의 남은 HOLD, 차량 추종 오차가 있는 재사용 연결, 센서 가림·연석 미검출·GPS 오차·자기 반사·미끄럼은 별도 검증/개선이 필요하다.
- 자유 셀 0.3초 만료, 모든 필수 센서의 신선도, GPS 정합, 현재 조향을 유지한 제동, 코어 20ms·callback 35ms 무효화 조건은 유지한다. 전체 50ms 목표의 ROS 큐·CAN·액추에이터 포함 계측은 남아 있다.
- `/avoid_v2/plan`과 `/avoid_v2/path`의 그림자 출력 단계이며 MGM·CAN 속도 제어 및 E-stop을 새로 연결하지 않았다. 실차 제동·조향 모델 확인 없이 이 변경을 실제 정지 보장으로 해석할 수 없다.

78회 기록의 코어 최대 계산 시간은 18.219ms다. 벽시계 예산은 결과 무효화 기준이며 운영체제 수준 실행 기한 보장이 아니다.
