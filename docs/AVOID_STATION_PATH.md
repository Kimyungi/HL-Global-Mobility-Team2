> 추가 변경: v2는 회피 TTC/avoidable로 E-stop을 만들지 않는다.
> 장애물 없음 + 회피 참조 무효 + GPS 참조 유효이면 MGM은 GPS로 전환한다.
> 차선이 없어도 GPS를 사용하며 신호 해제/회피 완료를 기다리지 않는다.

> 2026-09-14 SAFE_STOP 정책 변경: v2는 7개 센서 전체 상실일 때만 SAFE_STOP이다.
> 아래 경로 실패 정지는 `reference_motion_blocked=true`인 출력 대기로 동작하며,
> SAFE_STOP_REFERENCE_INVALID로 분류하지 않는다. 유효 제어점 없는 이동은 허용하지 않는다.

# GPS station 기반 3차 회피 경로

2026-09-14 사용자 지정 방식. 운영 노드는 `gps_cubic_path.GpsCubicPlanner`를
사용한다. `path_planner.py`의 과거 5차·고정 경로 방식은 과거 재현 테스트용이며
운영 노드에서는 선택하지 않는다.

## 좌표와 station

`stack_gps`가 CSV를 읽어 기존 GPS 추적기의 누적거리 station을 계산한다.
`GpsPath`는 단일 주행 기준점 외에 `waypoint_station_m`, `waypoint_stations`,
`waypoint_points`, `waypoint_window_valid`를 전달한다. 배열은 현재 station-2m부터
station+8m까지 원본 CSV 꼭짓점과 보간된 양 끝점이며, 경로 끝에서 잘린다.
station은 인덱스나 차량까지의 직선거리가 아닌 CSV 선분 길이 누적값이다.

이 창의 점은 단일 기준점과 동일한 차량 좌표계·GPS 자세·reference_stamp를
사용한다. 회피 노드는 같은 메시지의 ENU 위치와 실제 헤딩으로 고정 좌표계에
옮긴다. CSV가 순차 전환돼도 메시지 안의 좌표 변환은 동일하다. 경로 식별자가
바뀌면 이전 회피점과 완료 상태를 초기화한다. 접선 추정 헤딩, GPS/창 소실 시에는
CAN 위치나 단일 GPS preview로 대체하지 않고 경로를 무효로 내보낸다.

## 매 스캔의 경로 생성

1. 앞범퍼 전방 3.5m 미만·차량 중심선 좌우 0.5m에서 장애물을 검출한다. 검출 유지
   히스테리시스는 0.4m다. 연결된 LiDAR 윤곽 전체로 여유 공간의 회피점 G를 고른다.
2. 현재 GPS station을 s라고 할 때 A=웨이포인트(s+1m)를 진입 곡선 시작점으로 쓴다.
3. G를 현재 경로의 앞으로 남은 웨이포인트 선분에 투영한 누적거리를 sG로 구한다.
   복귀점 B=웨이포인트(sG+2.7m)를 선택한다. +2.7m는 주행 방향 순서이며 차량 뒤로
   2.7m라는 뜻이 아니다. 창/CSV 끝을 넘으면 임의의 짧은 복귀점으로 대체하지 않는다.
4. A→G와 G→B를 각각 매개변수 3차 Hermite 곡선으로 연결한다. x(t), y(t)가 모두
   3차식이며 각 끝점과 접선 방향을 맞춘다. G 양쪽 곡선은 같은 접선 방향(C1)을
   갖는다. C2 곡률 연속을 강제하는 스플라인은 아니다.
5. 차량 사각형, 알려진 장애물 윤곽, 최소 회전반경 1.15m로 두 곡선을 검사한다.
   A에서 시작하는 진입 곡선이 불가능할 때만 현재 차량 위치에서 G로 다시 계산한다.
   차량이 접근해 A가 G보다 앞선 경우에는 현재 위치에서 남은 구간만 생성한다.
6. G 이후는 항상 B로 향하는 곡선이다. 뒤쪽이 아직 안 보인다는 이유로 직선
   꼬리를 추가하지 않는다. 현재/기억된 장애물과 충돌하면 기준점이 없다.
7. 새 경로만 출력하며 지나간 prefix는 제거한다. 재계획에 이전 경로 점을 누적하거나
   과거 station의 0.75m 이탈 검사로 계속 막지 않는다. 검출이 잠시 사라져도 G와
   sG를 유지하여 남은 곡선을 갱신한다. 매 유효 스캔마다 재계산하며, GPS station은
   GPS 추적기에서 센서 generation별로 갱신한 값을 사용한다.

## 관측 면 기준 목표점 탐색

최근접 거리는 검출·TTC에만 사용하고 목표점 x의 기준으로 사용하지 않는다.
전방 계획 영역(앞범퍼부터 검출 유지 거리 3.9m, 좌우 탐색 반폭+목표점 여유)에
걸친 **모든 연결 윤곽**의 앞뒤 범위, 원래 끝점, 좌우 극점, 앞뒤 중간 위치에서
단면을 잡는다. 면의 먼 쪽부터 검사하고, 끝을 지난 후보도 끝점+여유/2와
끝점+여유 위치에서 검사한다. 면은 영역 경계로 자르지 않는다.

각 단면에서는 모든 관측 선분을 `차폭/2 + 측방 여유 = 0.46m`만큼 팽창시킨
영역의 실제 좌우 점유 구간을 구한다. 선분 방향의 사각형과 양 끝의 원으로
구성한 영역이므로 대각선 면 끝의 둥근 여유 공간을 보존한다. 전체 윤곽의
최대 y 범위를 모든 x에 일괄 적용하던 보수적 사각 투영은 목표점 생성에 쓰지 않는다.
구간 사이와 바깥 후보에 추가 측방 여유 0/0.05/0.1/0.15/0.2/0.3m를 적용한다.

좌우 탐색 제한 ±2.5m, 실제 선분까지 거리·가림, 곡선의 차체 충돌·곡률 검사,
A→G→sG+2.7m 연결 방식은 그대로 적용한다. `avoid.depth_band_m`은 과거 구현
호환 설정으로 남아 있으며 현재 목표점 생성에는 사용하지 않는다.
면은 실제 관측된 **2D 연결 선분**이다. 가려진 뒷면이나 닫힌 물체의 체적을
추정하지 않는다. 면 기준 후보가 있어도 지정된 두 곡선이 검사에 실패할 수 있다.

## 실제 제어점과 완료

- 평시 회피 노드의 출력: GPS station+1m 점. 일반 LINE/GPS 주행의 소스 우선순위는
  MGM이 결정하며 이 변경이 일반 차선 주행을 모두 GPS로 바꾸지는 않는다.
- 회피 진입·통과 전: **선정한 장애물 옆 G 자체**를 `AvoidStatus.points[0]`로 보낸다.
- G를 지나면: **복귀 웨이포인트 B**를 제어점으로 보낸다.
- B의 station까지 0.25m 이내, GPS 경로까지 0.25m 이내, 헤딩 오차 20도 이내이고
  다음 GPS 연결 곡선도 검사에 통과하면 완료한다. 이후 MGM의 GPS_RETURN 정렬
  조건이 적용된다. 장애물 소실/시간 경과만으로 완료하지 않는다.

외부 기준점 개수는 1개이며 {x,y,yaw,curvature} 차량 좌표 규약을 유지한다.
G의 곡률은 진입 곡선 끝의 곡률이다. MGM의 기존 진입 블렌드·속도 램프는 유지한다.
GPS 창/경로가 무효면 빈 기준점과 빈 RViz Path를 발행한다. 일반 주행에서 장애물
대응이 활성화된 동안 MGM은 이 경우 차선으로 진행하지 않고 정지한다.

## 진단·실행

- `/perception/avoid_path`: 매번 갱신한 경로, 지나간 구간 제외, `base_link`.
- `/perception/avoid_station`: GPS station, anchor, side, return station 표시.
- `avoid planner:` 로그: 실패 사유, target 유무, pose=gps, 각 station,
  current_pose_fallback(현재 위치 재계획 여부), updates(갱신 횟수).
- 설정: `avoid.waypoint_anchor_m=1.0`, `avoid.waypoint_return_m=2.7`,
  `avoid.path_spacing_m=0.05`, GPS/자세 timeout 각 0.5초.
- 기존 통합 런처를 재시작하면 적용한다. 메시지 계약이 확장돼 GPS·회피·MGM은
  같은 `install_v2` 빌드를 사용해야 한다. `scripts/v2 check`가 새 계약을 검사한다.

현재 관측·기억된 2D 윤곽과 계획된 차량 footprint에 대한 검사다. 요청한 +2.7m 복귀
곡선에는 아직 관측하지 못한 구간이 포함될 수 있다. 숨겨진 장애물과 실제 제어기의
추종 오차까지 검증한 것은 아니며 실차 검증은 별도다.

## 스캔 사이 목표점 선택 안정화 (2026-09-14)

초기 선택은 기존 후보 순서를 따른다. 이후 후보를 GPS 접선 기준 좌우로 구분해
기존 방향부터 검사하고, 같은 방향에서는 이전 ENU 목표점과의 거리가 작은 순서로
검사한다. GPS 중심선 ±5cm는 중앙으로 구분한다. 차량 회전/횡이동으로 차량 Y의
부호가 바뀌어도 GPS 기준 좌우는 유지된다. 기존 방향의 모든 후보가 진입·복귀
검사에 실패하면 나머지 방향을 검사한다. 이전 목표점을 복사하거나 보간하지 않고
새 관측에서 생성된 후보만 사용하며, 곡률/차체 충돌 검사와 경로 생성 방식은 유지한다.
양쪽 실패 시 경로/제어점은 비우고 방향 선호만 다음 스캔까지 기억한다.
플래너 reset은 목표점과 방향 선호를 함께 초기화한다.

검증: Python 회피 테스트 150개, HTML/Python 비교 77개 통과.
45° 장애물의 1cm 관측 변화 재현에서 최대 목표 이동은 1.828m에서 0.0553m로
줄었고 좌우 전환은 없어졌다. 이는 정지 차량의 합성 스캔 재현 결과이며 실차
조향 응답이나 모든 배치에서의 목표 이동 상한을 의미하지 않는다.
