# 두 장애물 연속 회피 레퍼런스 패스 설계안

2026-09-14. **구상 단계이며 운영 코드와 HTML에는 아직 적용하지 않았다.**

핵심은 기존 `A → G → B`를 `A → G1 → G2 → B2`로 확장하는 것이다.
각 장애물의 관측 면에서 기존 방식으로 회피점을 하나씩 선택하고, 세 구간 모두
현재 `GpsCubicPlanner._curve()`의 3차 Hermite 곡선으로 연결한다.
첫 장애물 뒤의 복귀점 B1은 이 경로에 넣지 않는다.

```text
현재: A ──3차── G1 ──3차── B1(웨이포인트)
추가: A ──3차── G1 ──3차── G2 ──3차── B2(웨이포인트)
제어점 순서:     G1          G2          B2
```

## 1. 현재 코드에서 확인한 제한

- `path_io.py::_path_goals()`는 여러 관측 면에서 후보를 만들지만 결과는 장애물
  식별 정보가 없는 평평한 `(x, y)` 목록이다. 후보 두 개가 서로 다른 장애물에서
  생성됐는지 알 수 없다.
- `gps_cubic_path.py::GpsCubicPlanner`는 `goal`, `goal_station`, `goal_side`를
  각각 하나씩 보관한다. 각 후보마다 진입과 GPS 복귀 두 곡선만 검사한다.
  장애물 두 개의 윤곽을 검사할 수는 있어도 회피점 두 개를 경유하지는 못한다.
- `_path_goals()`의 단면 생성 대상은 앞범퍼 기준 검출 유지 거리 3.9m까지다.
  뒤 장애물이 스캔에 보이더라도 이 영역 밖이면 자체 후보를 생성하지 못할 수 있다.
- `node.py`는 전방 검출이 true일 때만 새 후보를 전달한다. 첫 장애물을 지나
  차량 중심의 검출 통로가 비면, 보이는 두 번째 장애물을 새 후보에 반영하지 못할 수 있다.
- `manager_step.cpp`는 무검출 상태에서 회피 참조가 무효면 GPS로 바로 전환하며,
  유효 참조라도 `avoid_max_cycles`에 도달하면 GPS_RETURN으로 전환한다.
  따라서 플래너에 G2만 추가하고 완료 플래그만 늦추는 수정으로는 부족하다.

## 2. 장애물별 후보와 연결 대상 선정

기존 `scan_surfaces()`가 만드는 연결 윤곽을 출발점으로 사용한다. 이 윤곽은
물체 인식 결과가 아니므로, 윤곽 두 개를 곧바로 장애물 두 개로 간주하지 않는다.
관측 윤곽을 ENU로 변환하고 GPS 경로에 투영한 station 범위와 횡방향 범위로
연관시킨다. 스캔 사이에는 ENU 위치·범위의 근접/겹침으로 식별자를 유지한다.
동일 물체의 분리 반사 여부가 불명확하면 하나의 회피 대상으로 묶고,
가려진 공간을 새 관측 선분으로 연결하거나 물체 뒷면을 만들어내지는 않는다.
연관 거리와 범위 겹침 허용값은 실제 스캔 재생으로 정할 구현 파라미터다.

진행 순서는 차량 x나 최근접 거리 대신 GPS station으로 정한다. 앞뒤 station
범위가 분리된 두 대상 O1, O2에 대해 각각 후보 집합 C1, C2를 만든다.
횡으로 나란한 장애물이나 station 범위가 겹치는 배치는 기존 통과 공간 탐색을
사용하며, 억지로 앞뒤 두 대상으로 나누지 않는다.

후보 생성 자체는 현재 방식을 재사용한다.

1. 대상별 관측 면에 `surface_goal_sections()`를 적용해 앞뒤·끝점 단면을 만든다.
2. 각 단면의 `surface_intervals()`에는 **모든 관측 면**을 전달한다.
   O1 후보를 만들 때도 O2와 벽이 차지하는 공간을 제외한다.
3. 기존 `gap_centers()`와 추가 측방 여유 0/0.05/0.1/0.15/0.2/0.3m,
   탐색 반폭 ±2.5m, `_target_clear()`의 거리·가림 검사를 유지한다.
4. 결과에 `obstacle_id`, `goal_enu`, `goal_station`, `goal_side`를 붙인다.
   G1과 G2는 서로 다른 대상에 속하고 `sG1 < sG2`여야 한다.

뒤 장애물 탐색은 회피 에피소드 중 유효 스캔마다 실행한다. 기존 3.5m 진입 검출과
0.4m 히스테리시스는 유지하고, **후속 대상 후보 탐색 영역만** 관측 가능한 전방과
GPS 창으로 넓힌다. GPS 경로의 주행 통로 또는 현재 회피/복귀 경로의 차체 영역에
걸리는 후속 대상을 선정하며, 경로와 무관한 옆 물체까지 연결하지 않는다.

현재 GPS 창은 station 기준 뒤 2m~앞 8m다. O2와 G2를 투영할 경로가 있고
`sG2+2.7m`도 창 안에 있어야 완전한 연결 경로를 만들 수 있다. 필요한 후속 대상은
보이는데 복귀 station이 창 밖이면 `return_window_unavailable`로 구분한다.
더 짧은 복귀점으로 잘라 맞추거나, O2를 무시한 경로를 발행하지 않는다.
8m보다 넓은 범위의 선행 계획이 필요할 때 GPS 창 확장을 별도 변경으로 검토한다.

## 3. 기존 곡선 생성 방식 재사용

`W(s)`를 기존 GPS station 보간 함수라고 하면 다음과 같다.

```text
A     = W(s_current + 1.0m)
Gi    = 기존 관측 면 기반 후보 중 선택한 점
sGi   = Gi를 전방 GPS 경로에 투영한 station
yawGi = W(sGi)의 접선 방향
B2    = W(sG2 + 2.7m)

entry   = _curve(A,  G1, all_obstacles)
between = _curve(G1, G2, all_obstacles)
exit    = _curve(G2, B2, all_obstacles)
path    = entry + between[1:] + exit[1:]
```

`_curve()`의 접선 길이 배율 1/1.25/1.5/1.75와 최소 최대곡률 후보 선택,
`_safe()`의 최소 회전반경 1.15m·차체 사각형·측방 여유·샘플링 여유를 유지한다.
모든 구간을 O1/O2와 나머지 현재·기억 윤곽에 대해 검사한다.
G1, G2에서 양쪽 곡선의 접선 방향은 같게 한다. 현재처럼 구간별 접선 길이가
달라질 수 있으므로 공통 매개변수의 미분 크기 일치나 C2 곡률 연속은 보장하지 않는다.

진입 곡선만 실패하면 현재 구현처럼 차량 현재 위치에서 G1으로 재시도한다.
G1→G2 또는 G2→B2 실패를 직선 연결이나 부분 경로 발행으로 우회하지 않는다.
후보 쌍 전체를 검사해 세 구간이 모두 통과한 경우에만 채택한다.

단일 장애물 경로에서 고른 G1을 먼저 확정해서는 안 된다. 그 G1에서 G2로
연결할 수 없을 수 있으므로 C1×C2를 함께 평가한다. 각 장애물별로 기존 GPS 기준
좌우 방향과 이전 ENU 목표점에 가까운 새 후보를 우선한다. 다른 방향 조합도
앞선 조합이 모두 실패하면 검사한다. 반대편 장애물 사이의 S자 경로도 동일한
곡률·충돌 검사에 통과할 때만 채택한다. 구간별 검사 결과를 후보별로 캐시하여
후보 쌍마다 동일한 진입·복귀 곡선을 반복 계산하지 않게 한다.

## 4. 플래너 상태와 매 스캔 재계획

단일 `goal` 대신 최대 두 개의 `goals`와 `active_goal_index`, 대상별 관측 기억,
마지막 `return_station`, 두 장애물 회피 진행 여부 `chain_pending`을 저장한다.
좌표는 기존처럼 ENU에 보관하고, 출력 때 차량 좌표계로 변환한다.

| 내부 단계 | 생성하는 남은 경로 | 외부 제어점 |
| --- | --- | --- |
| G1 통과 전 | A 또는 현재 위치 → G1 → G2 → B2 | G1 |
| G1 통과 후 | 현재 위치 → G2 → B2 | G2 |
| G2 통과 후 | 현재 위치 → B2 | B2 |
| B2 도달 | 기존 다음 GPS 연결 검사 | GPS station+1m |

진행 인덱스는 검출 해제 여부와 독립적으로 증가한다. G1을 지난 뒤에도 O2 때문에
`obstacle_detected=true`일 수 있기 때문이다. GPS station이 해당 목표 station을
지났고, ENU에서 목표의 GPS 접선 방향으로 차량이 목표를 지났음을 함께 확인한다.
허용 오차를 둔 통과 판정은 한번 성립하면 유지하며, 순간 차량 x 부호나 최근접
경로점만으로 G2를 건너뛰지 않는다. 목표점 통과와 장애물 후단 통과는 구분한다.
G1 뒤에도 차체 뒤쪽이 O1에 닿지 않도록 O1 윤곽은 충돌 검사에 계속 포함한다.

매 유효 스캔마다 남은 구간을 새로 만들고 `_publishable()`로 지나간 prefix를
제거한다. 첫 장애물 회피 중 O2가 새로 보이면 아직 남은 G1 뒤에 G2를 추가하고
복귀점을 B2로 변경한다. 이미 G1을 지났거나 B1으로 복귀 중이면 현재 위치에서
G2→B2를 연결한다. 지나간 G1으로 되돌아가는 구간을 재생성하지 않는다.

확정된 O2가 잠시 가려져도 해당 목표·station·ENU 윤곽 기억을 유지한다.
기억된 목표로도 매번 전체 남은 구간을 다시 검사한다. 검출 소실만으로 G2를
삭제하거나 B1으로 복귀하지 않는다. 현재의 최초/최근 전체 윤곽 기억만으로는
중간에 새로 본 O2가 사라질 수 있으므로 대상별 마지막 관측을 별도로 유지한다.
기억 해제는 통과/완료 또는 명시적인 세션·경로 reset에 연동한다.

## 5. MGM의 조기 GPS 전환 방지

`AvoidStatus`에 `bool chain_pending`을 추가하는 안을 사용한다.
이는 실제 전방 검출을 나타내는 `obstacle_detected`와 별개의 두 장애물 회피 진행
상태다. 연속 회피가 필요한 O2를 확정한 시점부터 B2 완료까지 true이며,
경로 생성 실패나 GPS 창 부족으로 제어점이 없어도 true를 유지한다.
경로가 성공한 경우에만 true로 만들면 실패 시 GPS 우회가 남는다.
단일 장애물 에피소드에서는 false여서 기존 전환 정책을 유지한다.

MGM에서는 다음 두 전환에 `!chain_pending` 조건을 추가한다.

- 무검출 + 무효 회피 참조 → GPS 즉시 전환.
- 무검출 + `avoid_max_cycles` 도달 → GPS_RETURN.

`chain_pending=true` 동안 AVOID_ACTIVE를 유지한다. 유효 제어점이 없으면 기존
`reference_motion_blocked` 출력 대기를 적용한다. 완료 조건은 마지막 B2를 기준으로
기존 station 0.25m·GPS 경로 오차 0.25m·헤딩 20°·다음 GPS 곡선 검사다.
완료 시 같은 갱신에서 `chain_pending=false`, `maneuver_done=true`를 전달하고,
기존 MGM GPS_RETURN의 0.1m·20° 정렬 조건을 거쳐 종료한다.

`chain_pending`은 참조점 유효성과 독립적으로 전달해야 한다. 유효 스캔에 근거한
상태 갱신을 받되, 잘못된/오래된 입력의 기본 false 값이 기존 true를 지우지 않게
MGM에도 상태를 유지한다. 해제는 신선한 완료 또는 명시적인 reset/기존 상위 상태
전환으로 한정한다. 라이다 상실에 따른 `!avoid_allowed`, 신호 해제 시 회피 초기화
등 다른 해제 경로도 함께 검토하여 정상 주행으로 복귀할 때 잠금이 유실되지 않게 한다.
외부 정지·후진·미션의 기존 우선권은 유지한다.

외부 `AvoidStatus.points`는 계속 **1개**다. 경유점 두 개를 CAN 제어점 배열에
동시에 넣지 않고 G1 → G2 → B2 순서로 넘긴다. 각 Gi의 yaw/curvature는 현재
재생성된 진입 구간 끝값을 사용한다. reference_stamp의 센서 generation 규칙도 유지한다.

## 6. 변경 대상과 검증 기준

| 파일/영역 | 예정 변경 |
| --- | --- |
| `stack_avoid/path_io.py`, `surfaces.py` | 대상 연관, 대상별 후보, 후속 탐색 |
| `stack_avoid/gps_cubic_path.py` | 후보 쌍 선택, 세 곡선, 진행 인덱스, 대상별 기억 |
| `stack_avoid/node.py` | 회피 중 무검출 스캔에서도 후보 갱신, 진행 상태 발행 |
| `fma_interfaces/msg/AvoidStatus.msg` | `chain_pending` 추가 |
| MGM 메시지 매핑·core·replay/dump·관련 backend | 상태 전달/보관, 조기 종료 조건 수정, 계약 일치 |
| HTML 실험실 `engine.js`, `app.js`, 빌드 결과 | G1/G2/B2·활성 제어점 표시, Python과 동일 알고리즘 |

필수 재현 장면은 다음과 같다.

- 단일 장애물: 기존 선택·경로·출력·MGM 동작 회귀 없음.
- 같은 쪽의 앞뒤 두 장애물: 세 곡선이 G1/G2를 지나 B2에서 끝남.
- 반대쪽 두 장애물: 가능한 S자만 허용하고 급곡률·차체 충돌이면 빈 참조.
- 첫 장애물 도중/복귀 도중 O2 추가: B1 대신 B2, 지나간 G1 재방문 없음.
- G1 통과 후에도 전방 검출 유지: 제어점이 G2로 정상 전환됨.
- O2 일시 가림 또는 검출 통로 밖: G2 기억 유지, 조기 GPS 전환 없음.
- 두 번째 복귀점 창 부족·GPS 소실·전 구간 실패: 빈 경로/참조, 완료 false,
  pending 유지, MGM 출력 대기. 입력 복구 후 새 경로 생성.
- 분리 반사/나란한 장애물: 같은 물체의 두 후보를 앞뒤 두 목표로 잘못 선택하지 않음.
- 타이머 만료·신호 해제·오래된 메시지·reset: 진행 상태 해제 계약 검증.
- Python/HTML 연속 스텝 비교 및 ROS MGM 통합 검사. 후보 수 증가 시 스캔 처리
  시간도 측정하여 현재 입력 timeout 안에서 동작하는지 확인.

설계 확인을 위해 기존 `_curve()`만 호출한 간단한 수치 검사를 수행했다.
