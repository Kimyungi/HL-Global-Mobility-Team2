# 두 장애물 회피점 고정

운영 플래너는 `FixedObstaclePlanner`다. `GpsCubicPlanner._curve()`와 선택된
python/native 계산식을 재사용하며 수식·샘플 간격·차체 여유·회전반경을 유지한다.

경로는 `GPS s+1m → G1 → G2 → GPS(sG2+2.7m)`다. 장애물이 하나면 G1 뒤로
복귀점을 잡고, 뒤 장애물이 관측되면 이미 발행한 G1은 그대로 둔 채 G2와 최종 복귀점을
추가한다. 동시에 두 장애물이 보이면 두 점을 거치는 전체 경로가 유효해야 발행한다.

- 고정 대상은 서로 다른 앞뒤 장애물에서 만든 회피점 G1/G2다. 진입점과 복귀점 두 개를
  고정한다는 의미가 아니다. 고정점의 ENU 위치·접선·GPS station을 보관한다.
- `vehicle station >= goal station`이면 해당 점을 통과 처리한다. G1을 통과해도 G2를
  재생성하지 않는다. 검출 소실, 차량 x좌표, 경과 시간만으로 통과 처리하지 않는다.
- 후진으로 이미 통과한 점을 다시 활성화하지 않는다. 통과하지 않은 점은 후진해도 유지한다.
- 고정된 두 점이 모두 있으면 후보 탐색을 생략한다. 곡선은 최신 차량 위치 기준으로
  재생성하고 최신 스캔 및 기억된 장애물과 충돌·곡률을 검사한다. 통과한 점은 경로에서 제외한다.
- 고정 경로가 막히면 점을 옮기거나 반대편 점으로 교체하지 않는다. 빈 경로를 발행해
  MGM의 기존 무효 reference 정지를 적용한다. GPS/스캔 손실 때도 옛 경로를 유효하게 재발행하지 않는다.
- 두 점을 통과한 뒤 최종 복귀 station 근처(기존 0.25m 허용), GPS 횡오차 0.25m 이하와
  yaw 오차 20도 이하, 무검출, 유효한 전방 곡선이 모두 만족돼야 planner done을 낸다.
  이후 MGM의 GPS_RETURN 종료 조건(횡오차 0.1m 이하 등)은 기존 그대로다.
- 세션 시작, 경로 변경, MGM 회피 비활성화/새 활성화 시 고정점과 통과 상태를 초기화한다.

장애물별 후보는 기존 연결 윤곽을 GPS station에 투영한 범위로 나눈다. 범위가 겹치거나
0.3m 이내로 이어진 윤곽은 한 대상으로 묶고, 앞뒤로 분리된 최대 두 대상을 사용한다.
이는 물체 종류/인스턴스를 인식하는 추적기가 아니다. 서로 가까운 물체·분리 반사점의
연관 판단에는 실제 스캔 확인이 필요하다. 병합은 후보의 소속만 정하며 관측되지 않은
윤곽 선분을 새로 연결하지 않는다. 단면 생성은 해당 대상의 면을 쓰고, 여유·가림·충돌
검사에는 모든 면을 사용한다. 뒤 대상은 유효 스캔 범위에서 찾되 최종 복귀점이 GPS
waypoint 창 밖이면 부분 경로를 발행하지 않는다.

`AvoidStatus.points`/CAN에는 현재 추종할 점 **한 개**를 기존 계약대로 보낸다.
내부적으로 G1/G2를 함께 보관하며 G1→G2→복귀점으로 현재 제어점을 바꾼다.
차량이 움직이면 차량 좌표계의 x/y는 달라지지만 ENU 고정점은 움직이지 않는다.
진입점은 계속 GPS s+1m이며, 고정한 것은 회피점이지 차량 좌표 숫자나 전체 곡선이 아니다.

기존 `AVOID_REFERENCE_LAB.html`은 새 고정점 로직을 반영하지 않은 이전 계산 모델이다.
첫 유효 경로 생성 자체가 실패한 경우에는 아직 고정할 발행점이 없다. 이 변경만으로
이전 현장 시험의 최초 후보 전멸이나 장면별 최악 계산시간을 해결했다고 볼 수 없다.
