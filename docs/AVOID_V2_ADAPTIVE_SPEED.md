# 벽 중앙 경로의 유동 속도 제어

> 수정 전 기록이다. 현재 수정 내용과 시험 결과는 [실패 수정 결과](AVOID_V2_FIXES.md)를 참조한다.

2026-09-15 · `New_Avoid_v2`

벽 사이 경로에 **통로 폭·곡률·조향 변화량에 따른 속도 계획**을 추가했다. 같은 3m 도로·차량 2대/3대 배치에서 일반 주행은 기존 고정 1m/s의 36/60회에서 **51/60회 완주**로 개선됐다. 나머지 9회는 HOLD이며, 모든 틈의 통과를 보장하지 않는다.

## 동작

1. LiDAR 자유 통로의 양쪽 경계와 중간점을 기존 방식으로 구한다. 자차·장애물은 길이 0.85m, 폭 0.62m이며 양쪽 0.15m 검사 여유를 유지한다.
2. 단면 폭에서 차폭·양쪽 여유를 뺀 잔여 폭을 계산한다. 잔여 폭 0.6m 이하에서 최저 속도, 1.5m 이상에서 순항 상한, 그 사이에서 선형으로 속도 상한을 정한다. 이는 튜닝값이며 통과 가능 폭 판정값과 다르다.
3. 곡률의 횡가속 상한과 단위 거리당 조향 변화량에 대한 조향 속도 상한을 함께 적용한다. 최대 조향각 0.476rad, 조향 속도 0.8rad/s, 조향 지연 시정수 0.33s를 유지한다. 저속에서는 추종 선행 거리도 줄인다.
4. 앞범퍼와 관측·명령 지연을 고려해 제한 구간을 앞당긴다. 뒤쪽 단면 두 개의 제한도 유지해 좁은 통로를 빠져나오는 중에 조기 가속하지 않게 한다. 뒤에서 앞으로 `v_i² ≤ v_(i+1)² + 2 a Δs`를 적용해 감속을 준비한다.
5. 실제 측정 속도에서 시작해 가속 0.35m/s², 계획 감속 0.70m/s² 이내로 속도를 변경한다. 새 계획의 최초 50ms는 주행 중 측정 속도를 유지한다. 감속했다고 가정해 차량 위치를 순간 이동시키지 않는다.
6. 10Hz 새 관측에서 기존 경로가 아직 안전하고 현재 위치·방향·속도·조향과 일치하면 남은 속도 계획을 유지한다. 각 구간의 가감속·조향 속도·차체·제동 공간을 다시 검사한다. 장애물 추가나 자유 공간 만료는 재사용을 차단한다.
7. 속도마다 차체와 측정 조향을 유지한 제동 궤적을 확인한다. 유효 경로는 점별 속도와 0.1초 뒤의 요청 속도를 출력한다. 통과 경로를 검증하지 못하면 HOLD다.

시나리오의 속도 범위는 **0.2~1.0m/s**다. ROS 그림자 설정의 순항 상한은 기존 **0.6m/s**이며, 같은 유동 속도 코드를 사용한다. `AvoidPlan.path_speed_mps`는 `path`와 같은 길이의 속도 배열이다. `speed_limit_mps`와 `reference.v_suggest`는 현재 계획의 **100ms 뒤 요청 속도**이며, 경로 전체의 고정 상한이 아니다.

제동 거리 모델은 `v × (0.10 + 0.05 + 0.20) + v² / (2 × 1.0) + 0.20`이다. 1m/s에서는 1.05m, 0.2m/s에서는 0.29m다. 이 값은 실측 제동 성능의 보장이 아니다.

## 차폭보다 넓으면 모두 통과하는가

그렇지 않다. 차폭 0.62m에 현재 좌우 검사 여유를 더하면 최소 0.92m지만, 이는 평행 자세에서의 기본 조건일 뿐이다. 격자 해상도·표본 사이 검사 여유·차량 길이·회전 자세·최소 회전 반경·진입 및 제동 공간 때문에 더 큰 폭이 필요할 수 있다. 감속은 조향할 시간을 확보하지만 최대 조향각으로 정해지는 회전 반경을 줄이지 않는다.

## 검증 범위

코어 시험 7개 중 6개 통과. 동일 차량 시나리오 시험은 위 9회 미완주 때문에 실패다. 경로 복귀 시험은 20m 합성 경로를 벗어나도록 늘어난 재생 시간을 24초로 바로잡은 후 통과했다. ROS 인터페이스·회피·GPS 3개 패키지 빌드와 격리 ROS smoke 시험도 통과했다. [검사 로그](avoid_v2_adaptive_checks.txt)를 남겼다.

HTML의 5,834개 실제 코어 프레임에서 시간 적분·가감속·조향 속도·목표점 일관성을 검사했다. Chrome 1440px와 390px에서 각각 781개 UI 검사를 통과했다. 현재 속도와 100ms 뒤 요청 속도 표시도 검사에 포함한다. 78회 시나리오의 코어 최대 계산 시간은 9.72ms였으며, 전체 지연 계측값은 아니다.

새 단위 시험은 시간 기반 가감속 적분, 측정 속도에서 시작하는 경로, 정지 상태 출발, 새 장애물에 의한 기존 경로 무효화, 가감속·조향 속도 한계, 좁은 벽 통과를 검사한다. HTML도 실제 C++ 코어의 속도 계획을 0.1초씩 실행하며 현재 속도와 요청 속도를 표시한다.

실행 연결은 여전히 그림자 단계다. ROS 진단 경로·속도 발행까지 구현했으며 MGM·CAN의 실제 속도 제어와 E-stop은 연결하지 않았다. 10Hz 관측과 20ms 코어 예산을 유지한다. 전체 50ms 목표는 ROS 대기·직렬화·CAN을 포함한 실측 검증이 남아 있다.
