# ESTOP 스테이션 계약 — 2026-09-19

사용자의 새 지시로 기존 PR #108 후진 회복 계약을 대체한다.
독립 E-stop을 사용하지 않는 상위 MGM ESTOP 구조는 유지한다.

## 현재 런처 상태

**스테이션을 내일 지정할 때까지 ESTOP 감지 비활성화.**
`estop_station_zone_id=0`을 명시하고 과거 `estop_recovery_node.py`를 실행하지 않는다.
운전자 정지, CAN 고장, GPS/참조 유효성 등 다른 정지 조건은 유지한다.
감지 비활성화는 장애물이 없다는 판정이나 실차 운행 검증 결과를 뜻하지 않는다.

## 스테이션 연동 TODO

- 사용자는 경로 CSV의 `state` 값으로 스테이션을 지정할 예정이다.
- `state=6` 연속 행 구간을 제안했으나 사용자는 현재는 **코멘트로 남길 것**을 요청했다.
  따라서 번호·범위는 확정하지 않고 CSV/경로를 수정하지 않았다.
- 내일 실제 CSV 번호·시작/끝을 확정하고 현재 위치 기준 안정된 station membership으로
  연결해야 한다. preview 위치를 스테이션 진입으로 사용하지 않는다.
- 코어의 `estop_station_zone_id`는 검증된 membership을 선택하는 연결점이다.
  현재 production 값 0을 임의의 기존 zone으로 대체하지 않는다.
- 스테이션 이탈 확인 후 재진입 허용. 같은 스테이션 안에서는 stop/go나 GPS 소실로
  재진입 제한이 풀리지 않는다. 새 prepare 세션에서는 상태 초기화.

| 상위 정지 | 운전자/CAN 정지 중 해제하지 않음. 인가 복구 뒤 새 clear 관측 필요 |

스캔의 유효한 `+inf`는 센서 측정 범위 안의 no-return으로 취급한다. 전방 사각형
방향의 NaN/범위 밖 값, 충분하지 않은 측정 범위나 시야는 clear로 취급하지 않는다.
기존 센서 준비 조건 때문에 출발 준비에서는 여전히 네 LiDAR가 필요하다.
과거 `/planning/estop_recovery`의 속도나 done을 받더라도 상위 ESTOP은 무시한다.

snapshot에는 전방 최대 군집 폭과 clear 관측이 추가되어 raw dump를 **v41**로 올렸다.
과거 v40 replay 도구는 `build_v2/replay_archive/v40_local/`에 보관했다.

전방 영역·폭·군집 분리·무효 스캔 단위시험, 진입/종료/재진입·기존 회복 명령 무시
